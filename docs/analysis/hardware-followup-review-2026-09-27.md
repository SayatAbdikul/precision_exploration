## Actionable findings

### P1: The physical summary records collateral different from the executed run

`tools/hardware/ics55_ecc_pilot_summary.py:72–82` imports the earlier Yosys
matrix's RVT typical-corner Liberty identity and ordinary LEFs. The executed ECC
run instead loaded both RVT and LVT `ss_rcworst_1p08_125` libraries and the
`_ecos.lef` technology and cell files. The routed netlist uses both VT families.

Evidence relative to the implementation root:

- `artifacts/ppa/ics55-hardware-foundation/integer4-ecc-readonly-runtime/runs/default/Synthesis_yosys/log/Synthesis.log:22`
  loads RVT slow Liberty; line 25 loads LVT; line 1180 records their merge.
- The same log at lines 1469–1475 identifies the ecosystem LEFs and slow libraries.
- `artifacts/ppa/ics55-hardware-foundation/integer4-ecc-readonly-runtime/runs/default/route_ecc/log/route.log:115`
  lists the actual three LEFs.

The route itself is real, but its summary cannot currently support reproducible
comparisons with the earlier RVT-only typical-corner matrix. Record and hash the
actual generated configuration, all executed collateral, corner, VT families,
constraints and source snapshot. Keep the two runs' provenance separate. Update
the capability/checklist records so the later success and remaining gates agree.

### P2: Timing and placement can accept stale output files

`public/pdk_flow/ics55/validate_integer.py:62` and `:83` accept an existing report
or DEF if the new executable exits zero. A temporary-file reproduction with
`/bin/true` showed both functions accepting old files despite producing no new
output. Use fresh run directories or remove invocation-owned outputs before
execution, and add regressions for stale output plus a zero-exit command.

### P2: Local bank accounting omits bias-load writes

`public/analysis/memory_schedule.py:154–155` includes bias reads and storage,
but `:189–200` counts W/A fills and output writes without the write that loads
bias into its local bank. Under the documented per-spatial-tile bias-fetch
schedule, fixing that omission lowers the throughput bound in **121/625 rows**.

Independent witness: FP8 E4M3FN pointwise input/output `(1,1,1,8)`, weight
`(1,1,1,1)`, tile `1×8×1`, one 64-bit bank, 100 MHz, 64 MAC/cycle,
100 GB/s external bandwidth, no double buffering. W/A/O/bias require
1/8/1/1 words. The model returns 10 local writes; filling W+A+bias and storing
O requires 11, reducing 80 M MAC/s to at most 72.727 M MAC/s.

Also specify whether output uses a direct bypass or requires bank reads for
draining to external memory. The latter accesses are currently absent; a bypass
can legitimately avoid them. Hash the shared `memory_model.py` dependency in
the schedule generator's provenance as well.
